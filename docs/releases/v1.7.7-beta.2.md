# ThreadPilot v1.7.7-beta.2 — Game Boost & efficiency mode

**Pre-release for testing, not a stable release.** This build includes all changes since v1.7.6, including the latest local Game Boost work. v1.7.6 remains the stable/latest release; this beta is not distributed through winget, Chocolatey or stable automatic updates.

## What's included

- **Game Boost (opt-in):** topology-aware CPU Sets for the game and explicitly listed background apps, optional Above Normal priority, persistent-rule precedence, restoration when the game exits or Game Boost is disabled, and crash-recovery journaling. Activity now shows session start/end, what was applied or left unchanged, and restore results.
- **CPU topology fixes:** Intel P/E cores use the highest Windows EfficiencyClass for P-cores; AMD CCD groups come from real L3 groups and sizes, including 6+6 layouts.
- **Efficiency mode / EcoQoS:** Windows decides / On / Off, independently of CPU priority, for live processes and saved rules. A warning explains the global Power Throttling override.
- **Rules and backup reliability:** persistent rules are included in configuration backups; imports are validated and rolled back on failure; overlapping rules have deterministic precedence and conflict reporting.
- **UI refresh:** labelled navigation, clearer Process and Rules editors, priority undo, Windows 11-style Settings/Tweaks, remembered layout and filters, scaling fixes, and seven-language localization.
- **CI/release fixes:** native EcoQoS tests now run on a Windows 11-era kernel (Server 2025), rather than Server 2022 which rejects power-throttling read-back. Beta tags remain pre-release and cannot replace the stable/latest release or enter the winget publication job.

## Validation status — hardware testers needed

**Game Boost is not yet validated on real dual-CCD Ryzen / dual-CCD X3D or Intel hybrid hardware, and comparative gaming benchmarks are still pending. No FPS improvement is claimed.**

The previous QA covered a single-CCD Ryzen 7 5800X3D and a clean Windows 11 VM: UI/settings, session detection, optional priority, respecting manual changes and rules, and crash recovery. Real Windows CPU Set apply/read/restore calls were tested with a simulated dual-L3 topology; that is not a substitute for real multi-CCD hardware. Anti-cheat/protected-game behavior still needs real-game testing.

EcoQoS itself (not Game Boost) was independently verified by @SA-Mousavichashmi on an Intel i5-12500H, Windows 11 build 26300.9711: On/Off/system-managed, persistent rules, independent CPU priority and protected-process failures.

We especially need reports from:

- **AMD dual-CCD X3D:** 7900X3D / 7950X3D / 9900X3D / 9950X3D. Verify that the game uses the V-Cache CCD and listed background apps use the other CCD; check for interaction with AMD chipset-driver core parking.
- **AMD equal-CCD CPUs:** e.g. 7950X / 9950X. Automatic should leave the game's placement to Windows and move only listed background apps; Isolation also places the game on CCD0.
- **Intel hybrid CPUs:** 12th–14th gen / Core Ultra, where supported. Verify game on P-cores and listed background apps on E-cores, especially in heavily multithreaded games.

Game Boost conservatively leaves CPU Sets unchanged on unsupported/single-CCD CPUs, incomplete topology, or fewer than six physical cores on the game side. A laptop with fewer than six P-cores can therefore correctly report that Windows decides. Optional priority is separate.

## Quick test procedure

1. Export a configuration backup. Record your CPU, Windows build (`winver`), chipset-driver version, and for AMD whether the `amd3dvcache` service is installed. Keep power plan, game settings and background load consistent.
2. In **Tweaks / Ottimizzazioni → Game Boost**, leave **Above Normal off**, choose **Automatic**, add your game manually if it is outside a recognized library, and check the background-app list. Enable Game Boost, then bring the game to the foreground.
3. Read the topology decision on the Game Boost card and session events in **Activity**. Inspect actual process **CPU Sets** in ThreadPilot, System Informer or Process Lasso; Task Manager's classic affinity mask does not show soft CPU Sets. On dual-CCD X3D, expect 16 game logical CPUs for an 8-core V-Cache CCD or 12 for a 6-core CCD when SMT is enabled. On Intel, compare the game selection with the P-core thread count.
4. Alt+Tab: the session should remain active. Close the game or disable Game Boost: only changes owned by Game Boost should be restored. Existing rules and later manual changes should be respected. On equal-CCD AMD systems, repeat with **Isolation** and compare. Do not disable anti-cheat or bypass protected-process restrictions.
5. For performance, use CapFrameX or PresentMon with the same scene and **at least three runs per scenario**: (a) Game Boost off; (b) on, no background load; (c) on with browser video / Steam download; (d) same as (c), with Above Normal on. Compare average FPS, 1% lows, P95/P99 frame times and run-to-run variance.

## Known limits & safety

- Above Normal only raises a game that starts at Normal; a game at another priority is left unchanged.
- Manual selection of exactly the CPU Sets that Game Boost already applied cannot be distinguished from its own selection and may be cleared at session end unless saved in a rule.
- Detection requires a recognized library plus foreground activity, or a manually listed game. Add Battle.net/other custom-install games explicitly when needed.
- Applications can override their own QoS or CPU Sets. Protected processes can refuse access; ThreadPilot does not bypass protection.
- Artifacts are **unsigned** while code-signing enrollment is pending; Windows SmartScreen may warn. Verify SHA256 before running. Upgrading preserves settings; uninstalling removes ThreadPilot-owned user data.
